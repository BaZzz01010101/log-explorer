# Account and region Explorer

Historical revision: [0.1.13](saved-views-and-access-0.1.13.md) removes the advanced editor, remembers packaged AWS access and replaces resource favorites with saved views.

Version 0.1.7 adds one virtualized account → region → log group → log stream tree. Account entries represent configured AWS profiles; no STS identity request is needed. A single AWS account hides its account node. Offline fixtures remain explicitly identified. Expand regions independently, search group names across expanded regions, and continue group/stream pages automatically while scrolling.

Connections settings merges known profile names with existing configured profiles. Enable a profile and choose regions with searchable checkboxes; region location names and codes both match. Disabling a profile retains its selected regions. Disabling a region retains its connection ID, settings and open tabs. Visibility does not change session authorization or cancel queries in existing tabs. Manual connection editing remains available under Advanced connection settings.

Known regions come from the installed AWS SDK partition metadata (`@aws-sdk/core` 3.978.3): 38 public commercial, China and GovCloud regions. Custom configured regions remain selectable. This catalog is local metadata, not a query for account-enabled regions. Unsupported or not-yet-enabled regions report the underlying service error when queried. Known profile discovery uses the existing authorization-gated main-process API and remains unavailable in development and offline verification.

Each region has independent group/stream caches, request generations and opaque cursor tracking. Collapsed regions do not trigger initial requests; collapsing an account hides its descendants. Search changes discard obsolete responses. Refresh invalidates pending stream requests and reloads still-expanded groups. Disabling and immediately re-enabling a region cannot strand it behind an old request or replace fresh results with an old error.

Regression review reproduced and fixed inherited-property collisions for names such as `constructor`: profile enablement, region-search drafts, restored connection IDs and stream caches now use explicit own-key lookups. These are ordinary names, not object internals. Focused component tests cover each path, and packaged checks also use a restored `constructor` connection ID and profile name.

Resource identities include the connection ID, so identical names in different regions retain the correct source when opening, favoriting, selecting or dragging. Legacy duplicate profile/region connections display one region, preferring the selected connection; saved favorites and quick jumps for the other IDs remain available. Tree keyboard arrows navigate actual account/region/group/stream parents. Preview/permanent opening, details, source dragging and existing tab behavior are retained.

Focused tests cover migration and visibility, catalog choices and connection bounds, lazy/concurrent loading, stale replies, repeated tokens, refresh races, tree levels/keyboard behavior, profile toggles, custom regions and known profiles without connections. Native checks use hidden Electron windows with trusted Chromium input, isolated data and immutable AWS denial. They cover multiple regions/accounts, duplicate names, collapse/search/stream expansion, settings changes and natural restart. Screenshots are captured while the windows remain hidden.

Final verification and artifact hashes are recorded in [feature status](feature-status.md). All test evidence stays under `.tmp`. Real AWS credentials, profiles and account data are not accessed during verification. The Windows installer is unsigned; installation, physical OS input, macOS/Linux and real AWS interoperability remain outside these checks.
