# Inspector message overview and scroll ownership

- The main event overview retains severity, quick text and profile colors. AWS/local filters no longer fill its highlight lane with matches that every displayed event already satisfies.
- The inspector message has a compact four-lane overview for AWS, local, quick text and profile text matches. Positions come from rendered text fragments, including wrapped lines and folded-branch indicators. Consecutive marks merge proportionally; dense pixels combine colors. Click a lane or mark to reveal the nearest matching fragment on both axes. The native thumb remains usable.
- Message folding, wrapping, decoding, font/theme changes and resizing refresh measured positions. Work is coalesced and processed in bounded batches; selecting another event discards its predecessor's map. The map reflects rendered content and existing inspection/highlight limits, rather than inventing locations for unrendered text.
- Event rows remain visible during worker updates. The per-row preparation text and row-hiding styles are removed; worker bounds and cached highlight results remain in place.
- The inspector is a flexible column with fixed navigation/mode/copy controls. Only `.inspector-content` scrolls; inner raw/structured containers inherit that owner. Padding belongs to the inner content, so it cannot force the viewport past the bottom of a short pane. A shrinkable message basis reserves space alongside expanded information without imposing an overflowing minimum height.
- Very short inspectors use compact header/body spacing. This leaves actual message space above a horizontal scrollbar, rather than an apparently scrollable area containing only the scrollbar.
- **Event information** folds source metadata, timestamp and level. Navigation remains available. Its state is saved in each view as `inspectorInfoCollapsed`, defaults to expanded for old/new views, and passes the same workspace validation/restoration path as other view settings. Long metadata remains available through selectable custom tooltips.

Verification evidence stays under `.tmp`. Native checks use trusted input in isolated hidden offline Electron windows and cover prior-build reproduction, map colors/positions/navigation, wrapping/resizing, folded branches, short panes, per-tab restart state and delayed worker presentation. Real AWS calls and installer installation are outside this UI verification.

All 817 unit/integration tests and 33 targeted packaged desktop scenarios passed on the final build. Eight intended failures reproduced against 0.1.33. Native testing also exposed and corrected two short-pane sizing cases: viewport padding forcing overflow and a zero flex basis leaving no message space after resize. Independent review prompted both-axis navigation coverage; the late-column raw/structured check passes.
